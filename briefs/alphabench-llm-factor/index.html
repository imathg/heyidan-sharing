AlphaBench：LLM 做公式化因子挖掘，瓶颈在哪一环

date 2026-07-12 sources 3 domain hf-alpha-factor slug alphabench-llm-factor

论文 AlphaBench（香港城市大学 / 上海财经大学等）是首个面向公式化 alpha 因子挖掘（FAFM）的系统性 LLM 基准，用 CSI300（2020–2025 真实数据）+ Qlib 回测闭环，将「应如何用 LLM 设计因子挖掘 Agent」转化为生成 / 评估 / 搜索三个维度的量化评测。

本文归纳 AlphaBench 在评估维度给出一个明确限制：零样本下没有任何 LLM 能稳定判别因子优劣，但成对选择（pairwise）SFT 效果显著且可跨市场泛化。这两点直接决定了因子挖掘 Agent 的设计方式。

三个维度怎么测

论文 AlphaBench 将因子挖掘分成三个部分：

  1. 因子生成：Text2Alpha（自然语言→DSL 公式，84 Easy / 106 Medium / 121 Hard）+ 定向挖掘（给技术主题如波动率突破，8 大类 90 细分自主发挥）。
  2. 因子评估：Factor Ranking + Scoring，再分出两个原子任务，即 Signal Classification（有效信号 vs 噪声）、Pairwise Selection（两个公式二选一谁 RankIC 更优）。
  3. 因子搜索：CoE（经验链）/ ToT（思维树）/ EA（进化算法，LLM 当突变 + 交叉算子）。

论文 评测还加入严格质量过滤器：算子嵌套 ≤5 层、Qlib 算子合法性 + arity 校验、单因子两周计算 ≤30s、NaN ≤1%、Lookahead（用 Ref 等未来函数）强制标 Noise + 评分直接打 1 分。

核心发现：零样本判别力≈掷硬币

论文 零样本下，没有任何 LLM 表现出稳定的因子优劣判别能力：DeepSeek-V3 信号 / 噪声分类仅 0.46、成对选择 0.48（与掷硬币无异），即使 GPT-5 的成对选择也只到 0.64（SP500 上 0.52）。

论文 论文给出的解释是：LLM 只能看到纯文本公式，但因子真实绩效高度依赖执行上下文（调仓频率、信息滞后、平滑策略、市场风格），公式文本省略了这些执行变量，使纯公式的性能推断在数学上成为欠定问题。CoT 在评分排名任务中还会引入额外方差，降低 NDCG@K。

但成对选择（pairwise）SFT 效果极强

论文 SFT 的两条路径反差极大：

SFT 任务 结果
噪声二分类微调 彻底失效（过拟合特定市场噪声模式）
成对选择微调 GPT-4.1-Mini 在 CSI300 上 0.44→0.83（CoT 0.86），且 CSI300 微调直接评 SP500 仍保 0.64

论文 相对排序促使模型学习更本质的通用结构特征（算子单调性、窗口交互逻辑、分母防零鲁棒性、量价组合合理性），这些特征在不同市场间高度通用，因此跨市场迁移能力较强。搜索任务上 EA 总体表现最佳；Gemini-2.5-Flash / GPT-4.1-Mini 的成本效益最高；温度 0.75 在搜索效率、收敛和多样性间取得最佳平衡（过高如 1.5 会显著增加不合规公式并提高搜索成本）。

论文 生成维度最容易出问题的地方：Word Salad（长 CoT + 高温→输出乱码）；代码专用模型（Qwen2.5-Coder、CodeLlama-70B）在 FAFM 上无优势；Hard 难度集上 Accuracy 普遍大幅下降（GPT-5 0.99→0.10）。

落地建议

论文 论文 / 解读给出的工程取舍：

  1. LLM 零样本过滤不作为主路径：硬规则交给 Python AST，或把 LLM 微调成 pairwise 比较器，真实性能交回 Qlib / 自研回测做最终约束。
  2. SFT 输入用 AST / 算子图结构化 JSON，并补执行元数据（调仓频率 / lag / 板块 / NaN 处理），缓解"欠定问题"。
  3. 构建对比度高的 pairwise 训练集：将确定 Noise 与确定 Signal 配对。
  4. EA crossover 需要代码层约束运算符嵌套失控（nesting depth + Ref 检测），prompt 约束仅作辅助。

本文归纳 LLM 适合充当变异 / 杂交算子的候选生成器，回测承担最终约束。这是当前较稳妥的 LLM 量化因子挖掘路径：LLM 负责生成候选多样性，因子优劣交给 pairwise 微调模型或回测系统判定。
