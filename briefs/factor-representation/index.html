因子公式怎样表示，才能检查和控制替换

date 2026-09-06 sources 4 domain hf-alpha-factor slug factor-representation

把因子里的标准差换成方差，代码可能照常运行：输入都是数组，输出都是浮点数。但如果它位于价格标准化的分母，替换就把原本无量纲的结果变成了价格的倒数。只记录“用了波动率”看不出这个问题；只检查 Python 类型也看不出。

需要检查和控制替换时，因子表示至少要让人回答：换的是哪个位置，那里接受什么输入，替换后的计算还保留了什么含义。本文从几个公开实现与教学例子出发，讨论一种可供实现的分工：属性概括实现，公式图保留细节，替换检查绑定具体位置。它是工程设计归纳，不是已经验证有效的金融分类体系。

先把计算顺序留下来

设 r 是资产 × 日期的收益率面板，mean_time(r, 5) 对每个资产取最近五期均值，rank_assets 在同一时点对资产排名。下面两个教学公式包含相同的算子：

A = rank_assets(mean_time(r, 5))
B = mean_time(rank_assets(r), 5)

A 比较谁在窗口内平均收益更高；B 比较谁在窗口内经常排在前面。每日领先一点与偶尔大幅领先，对它们的影响不同。算子清单一样，不代表顺序可以交换。

作用轴也不能藏在名称里。Alpha101 明确把 rank 定义为截面排名，把 ts_rank 定义为窗口内时序排名。脱离这套定义，看到一个 rank(x)，并不知道比较的是同一天的不同资产，还是同一资产的不同日期。

抽象语法树（AST）把函数及其参数关系保存下来。若共享相同的纯子表达式，可以进一步表示成有向无环图（DAG）；是否共享要以输入、参数和求值语义相同为前提。图的价值在于保存“谁作用在谁上面”，而不是比文本多画几条边。对齐、缺失值、窗口端点和算子版本仍要有定义，否则同一张图也可能被两个执行器算成不同结果。

用一个分母看清检查对象

以价格序列 x 构造滚动标准化值：

m = mean_time(x, 20)
s = std_time(x, 20)
z = (x - m) / s

这是教学例子，不是交易建议。假设均值和标准差使用相同的二十期完整窗口，标准差按分母二十计算，结果与当前日期对齐。图中 x 同时进入均值、标准差和减法支路；m 是位置参照，s 是尺度参照。当前只考虑 s > 0 的窗口。

把 s 换成 var_time(x, 20) 后，浮点类型没变，输出形状没变，时间窗口也没变；但价格方差的单位是价格平方，除法结果不再无量纲。这可以由局部量纲规则发现：加减要求同单位，除法把分母的单位从分子中消去。

再把 s 换成 mean_time(abs(x), 20)。它与价格单位一致，也可以为正，量纲检查便不再足以拒绝；但新的分母衡量的是价格相对零点的水平，而不是围绕窗口均值的离散程度。即使数值可算，它也不再是原来的 z-score。

这个区别可以直接检验。把窗口中所有价格加上同一个常数，原分子与标准差都不变；平均绝对价格通常会变。替换改变了对价格平移的响应。这里得到的是公式性质的反例，不需要收益标签，也不能据此评价哪一个公式有预测力。

类型要服务于目标位置

DEAP 的强类型遗传编程（GP）要求一个算子的输出类型匹配下一个算子的输入类型，展示了把一部分非法连接挡在构造阶段的方法。不过，金融公式需要检查的内容通常多于 float 与 bool。

对上面的分母位置，可以逐项写出所需条件：

要保存的信息 在这个位置检查什么 仍不能证明什么
输入输出形状与作用轴 是每资产每时点一个值，且与分子对齐 输出数值符合原定义
单位与数值尺度 与价格同单位；百分数等表示口径一致 衡量的是价格水平还是离散程度
窗口和信息可得时点 所用数据在计算信号时已经可知 信号对未来收益有用
数值定义域 分母为正；缺失窗口按明确规则处理 对异常行情足够稳健
所需公式性质 例如保持价格平移不变性 所有金融含义都已保存

这张表是针对该使用位置的检查单，不是通用属性分类。换到一个只需要价格水平的分母，条件就会不同。因而一条替换记录应说“候选 B 能否放入公式 F 的这个输入位置”，不能只记成“A 与 B 可互换”；换另一个公式或反过来替换，都要重新检查。

PhySO提供了一个可借鉴的实现方向：在物理符号回归中，随着表达式生成，推导尚未填入的位置需要什么量纲，并限制下一步可选符号。它证明了局部约束可以进入生成过程；金融目标量、市场条件和可得时点却没有因此自动获得同样的推导规则。尤其收益率本来就无量纲，方差与标准差的区别不能靠基本物理量纲消掉。

写成 DSL，也不等于没有未来信息

领域专用语言（DSL）让公式只能通过一组明确定义的算子表达，方便分析依赖。但算子受控，不代表依赖必然因果。

Qlib 官方 API明确说明，Ref(feature, N) 的 N > 0 读取历史值，N < 0 读取未来值。它也提供窗口扩展接口，用来计算求值需要向左、向右多加载多少数据；文档同时提示，另一个历史回看长度接口不能正确处理某些嵌套 Ref。所以不能拿“用了 Qlib 表达式”或“求出了回看长度”当作无未来信息证明。

更完整的检查还要问：当日收盘价何时能被策略使用？财务字段取的是报告期，还是实际公开时间？历史数据是否带后续修订？这些由数据与执行合同决定。公式图能承载依赖，不能替缺失的数据事实作答。

属性摘要、精确公式与验证各管什么

到这里，可以把表示拆成三个互补用途。检索时用属性摘要找到“输入为收益率、包含滚动统计”的候选；检查时回到精确公式图，沿算子和数据依赖判断；做替换时，再把候选放进目标位置的条件里验收。一个概念目录或知识图谱可以帮助召回，但“属于同一类”本身不发放替换许可。

这套分工的价值需要靠真实公式检验：哪些错误能确定拒绝，哪些合法公式被误拒绝，哪些问题仍须执行测试或专业判断。有限样例和类型检查通过都不能代表完整覆盖。

最值得先做清楚的是边界：数值和依赖检查回答能否按规定计算；金融解释回答是否仍测同一对象；样本外实验才有资格回答替换是否改善预测与投资表现。关于第二层为什么容易被“同名指标”掩盖，可以继续看同是波动率指标，为什么不能直接互换。
